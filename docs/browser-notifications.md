# 브라우저 알림 — 1단계 + 열린 페이지 자동 알림 (v25, 2026-10-05)

- 로그인한 학생과 관리자에게 상단 권한 버튼을 제공한다.
- `notifications.js`가 권한 확인, 요청, 로컬 Notification 생성, 상태 UI를 담당한다.
- 권한 요청은 버튼 클릭에서만 실행한다. 거부 상태에서는 재요청하지 않는다.
- 허용 직후 `NISML 연구실 / 연구실 알림 설정이 완료되었습니다.`를 표시한다.
- 이미 허용된 버튼은 테스트 알림을 다시 표시한다. 시작/새로고침은 알림을 보내지 않는다.
- 권한은 기기·브라우저·사이트 origin에 귀속한다. 계정 개인 설정에 저장하지 않는다.
- 열린 대시보드가 `/api/notifications`를 약 30초마다 조회하여 새로운 논문·학회 발표(포스터 포함)·학술대회 등록/수정/삭제를 OS 알림으로 표시한다.
- 최초 조회는 기준값으로만 삼는다. 과거 기록은 재생하지 않고, 거부 중에 감지한 기록도 허용 후 재생하지 않는다.
- 한 번에 6건 이상 바뀌면 요약 알림 한 개를 표시한다. 클릭하면 알림 센터를 연다. 개별 알림 클릭은 해당 탭/검색 결과를 연다.
- 계정별·브라우저별 전달 ID를 보관하고 Web Locks 지원 시 여러 탭의 동시 전달을 막는다. 다른 컴퓨터에는 각각 전달된다.
- 배경 탭에서도 조회를 시도하지만 브라우저의 절전/탭 정지/OS 집중 모드에 따라 지연될 수 있다. 페이지를 닫거나 컴퓨터가 잠들면 실시간 수신하지 않는다.
- 현재 관리자 직접 발송과 닫힌 페이지 알림은 제공하지 않는다.

## 실제 Mac/Windows 확인

1. 허용된 학생 계정으로 HTTPS 대시보드에 접속한다.
2. 상단 `🔔 알림 허용`을 클릭한다. 자동으로 권한 요청이 뜨면 안 된다.
3. 브라우저 요청에서 허용을 선택한다.
4. OS 알림센터에서 `NISML 연구실 — 연구실 알림 설정이 완료되었습니다.`를 확인한다.
5. 새로고침 후 `🔔 알림 켜짐`을 확인한다. 새로고침으로 테스트 알림이 다시 뜨면 안 된다.
6. 버튼을 다시 눌러 테스트 알림을 재확인한다.
7. 별도 브라우저 프로필에서 거부를 선택하고, 재클릭 시 권한 창 대신 차단 안내가 나타나는지 확인한다.
8. 다른 컴퓨터/브라우저에서 허용된 계정으로 같은 대시보드를 연다. 초기 자료를 불러온 뒤, 별도 관리자 또는 학생 계정에서 실제 연구 기록을 등록/수정한다. 약 30초 뒤 새 OS 알림과 클릭 이동을 확인한다. 자동 검증용 가짜 기록을 운영 DB에 만들지 않는다.
9. 같은 자료를 새로고침해도 과거 알림이 다시 뜨지 않는지 확인한다.
10. Mac Safari/Chrome, Windows Chrome/Edge에서 확인한다. OS에서 해당 브라우저의 알림 허용과 집중 모드도 확인한다.

자동 테스트는 요청/거부/중복 클릭/허용 복원/예외/클릭 이동을 모의 검증한다. 클라우드 브라우저에서 사용자의 Mac/Windows OS 알림센터는 확인할 수 없다.

## 다음 단계: Web Push

- Service Worker 등록과 `push`, `notificationclick` 처리; `{title, body, target}` 페이로드 사용.
- PushManager 구독, VAPID 키, 계정별 여러 기기의 구독 저장·해지 API.
- 관리자 전용 작성/전체·학생·그룹 선택/발송 화면과 서버 권한 검증.
- 발송 서버, 만료 구독 정리(404/410), 실패 처리, 중복 방지, 기기별 수신 설정.
- 알림 클릭 시 같은 origin의 목적 페이지로 이동하고 기존 로그인을 확인한다.
- Web Push 전환 시 알림 생성 transport를 `ServiceWorkerRegistration.showNotification`으로 대체한다.
- NAS 또는 별도 설치 프로그램은 필요하지 않다. 서버 발송 경로는 2단계에서 추가한다.
- 도메인이 바뀌면 알림 권한 및 Push 구독은 새 origin에서 다시 받아야 한다.
