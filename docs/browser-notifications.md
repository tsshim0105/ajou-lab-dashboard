# Web Push (v26, 2026-10-05)

- `service-worker.js`는 캐시 없이 Push 수신과 알림 클릭을 처리한다. 페이지가 닫혀도 브라우저/OS가 Push 수신 가능한 상태면 알림을 표시한다.
- `web-push-client.js`는 등록·구독·서버 연결·기기 해제를 담당한다. 권한 허용은 사용자의 버튼 클릭에서만 진행한다.
- 상단 알림 버튼으로 구독하고 서버가 보내는 테스트 알림을 확인한다. 알림 센터에서 이 브라우저의 원격 알림을 끌 수 있다.
- Web Push 연결된 페이지에서는 기존 폴링 기반 OS 알림을 중단해 중복 전달을 막는다. 대시보드 안의 알림 목록 갱신은 유지한다.
- `server/web-push.mjs`는 RFC 8291 aes128gcm 암호화 및 RFC 8292 VAPID를 Web Crypto로 구현한다. 공개 RFC 예제와 바이트 단위 일치 검증을 수행한다.
- 비밀키는 Sites 런타임의 `WEB_PUSH_PRIVATE_JWK` secret에만 저장한다. 공개키 `WEB_PUSH_PUBLIC_KEY`, 연락처 `WEB_PUSH_SUBJECT`를 함께 설정한다. 키를 임의로 교체하면 기존 구독이 작동하지 않는다.
- 구독과 전달 ID는 별도 D1 테이블에 저장하고 API에서 다른 계정의 endpoint/auth 키를 노출하지 않는다. 학생 권한은 기존 서버 로스터와 동일하다.
- 저장된 연구 변경이 발송 대기 기록이다. 저장 성공 후 Worker background 작업으로 발송하고, 이후 데이터/알림 조회가 실패한 전달의 재시도를 진행한다. 정기적인 별도 재시도 스케줄러는 아직 없다. 24시간 TTL·최대 3회 시도다. Push 서비스의 접수는 OS 표시 확인을 의미하지 않는다.
- 404/410 구독은 제거한다. 여러 이벤트를 한 개 요약 Push로 묶을 수 있다. 대시보드가 닫혀 있어도 다른 사용자의 등록/수정/삭제가 발송을 시작한다. 홈페이지나 학회 공식 사이트를 무인으로 새로 조사하는 기능은 이 작업에 포함하지 않는다.
- Mac Safari/Chrome, Windows Chrome/Edge 실기기에서 구독→페이지 닫기→다른 계정으로 변경→OS 알림→클릭→로그인 및 해당 탭 이동을 검증해야 한다. 절전/브라우저 종료/OS 정책에 따른 수신 제약이 있다.
- 제목은 `NISML 대시보드`, 아이콘은 업로드된 연구실 로고다. 브라우저가 붙이는 출처 주소·브라우저 앱 아이콘은 웹 코드로 숨길 수 없다.
- 관리자 논문 수정 창 하단의 삭제 버튼은 확인 후 삭제 이력을 남겨 원본 자료 갱신으로 복원되지 않게 한다. 학생에게는 삭제 버튼을 제공하지 않는다.

## 실기기 확인

1. 학생 계정으로 접속하여 상단 알림 허용 버튼을 누르고 브라우저 권한을 허용한다.
2. 원격 알림 연결과 테스트 OS 알림을 확인한다.
3. 새로고침 후 알림 켜짐 및 연결 상태를 확인한다.
4. 페이지를 닫은 뒤 다른 계정에서 실제 논문·발표 정보를 변경한다.
5. OS 알림을 클릭하여 해당 탭으로 이동하는지 확인한다.
6. 거부한 브라우저에서는 재요청 대신 설정 안내가 표시되는지 확인한다.

자동 검증은 암호화 표준 예제·서버 권한·구독 저장·전달 중복 및 삭제를 확인한다. 사용자의 Mac/Windows 알림센터 표시는 실기기에서 확인해야 한다.
